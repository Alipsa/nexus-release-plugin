# v2.4.0 single-plugin verification — 2026-10-11

Implementation follows [the plan](../v2.4.0-single-plugin.md). Development version:
`2.4.0-SNAPSHOT`. No artifacts were uploaded during verification.

## Behavior covered

- Original plugin registers combined tasks only when its configuration block is called.
- Shared properties exist before registration and work under eager `withType`, `all`
  and `whenTaskAdded` consumer rules, as well as lazy `configureEach` rules.
- Decorated parent/nested construction and provider-based assignment work in Groovy
  and Kotlin; Kotlin uses explicit typed lookup after opt-in.
- All shared-property mappings, unset path conventions, parent credential/Portal URL
  inheritance, explicit overrides and updates after registration are checked.
- Dynamic Groovy DSL attempts to replace the private registrar, access the nested
  extension directly or replace any combined task provider fail.
- Root-only opt-out preserves unqualified subproject bundle/release selectors,
  real signed bundles and local mock-Portal uploads, custom root tasks and ordinary
  publishing. Subprojects ignore the switch. Changing it invalidates configuration cache.
- Default single-publication behavior and coexistence remain covered; missing publication
  and invalid boolean settings retain explicit errors. Opt-out without combined opt-in
  intentionally registers neither release workflow.
- Combined planning, signing preflight, guard, Maven preparation, bundling and status-only
  resume exercise strict configuration-cache reuse. Resume schedules only `releaseAll`.
- Existing safety and HTTP tests remain in the full build and compatibility selection.
  Combined timeout implementations were not changed; their non-inheritance is documented.

## Commands

Full build: `./gradlew build -PrequireShellHarness=true` with the locally installed JDK 17.
This includes `charsetTest`, the required Bash harness and plugin validation.

Compatibility command (each Gradle/JDK cell uses its matching JAVA_HOME):

```sh
./gradlew test \
  --tests '*WsClientTimeoutTest' \
  --tests '*CentralUploadApiTest' \
  --tests '*GradleCompatibilityMatrixTest' \
  --tests '*BundleMetadataTest' \
  --tests '*CombinedTasksTest' \
  --tests '*CombinedReleaseDslTest' \
  --tests '*RootReleaseTaskSelectionTest' \
  -PtestGradleVersion=<gradle> -PtestJavaVersion=<jdk> \
  -PrequireShellHarness=true
```

The new Groovy/Kotlin DSL and root-selector fixtures assert their actual daemon JVM
and Gradle versions. The CI `compatibility-test` filter includes all three combined
integration/DSL/selector classes. Logs and XML reports are retained locally under
`build/verification/v2.4.0/` (ignored build outputs).

## Publication checks

Generated Central and Portal implementation POMs plus the original plugin marker POM.
An inspection init script reported:

```text
DECLARED_PLUGIN_IDS=[se.alipsa.nexus-release-plugin]
PUBLICATIONS=[mavenCentral, pluginMaven, simplePluginPluginMarkerMaven]
```

Original implementation coordinates are preserved:
`se.alipsa.nexus-release-plugin:se.alipsa.nexus-release-plugin.gradle.plugin` for
Central and `se.alipsa.gradle:nexus-release-plugin` for the Portal implementation.
The original marker coordinates also remain unchanged. JAR inspection found only
`META-INF/gradle-plugins/se.alipsa.nexus-release-plugin.properties` and no
`ReleaseAllSupportPlugin` class. Old generated publication directories from prior
builds are not declarations and are not published.

`./gradlew publishPlugins --validate-only` rejects SNAPSHOT versions before validation.
`./gradlew publishPlugins --validate-only -Pversion=2.4.0` passed without upload;
the override does not change the repository version. Real publication requires a
release version and is outside this PR.

Matrix's external build/guide migration remains a consumer rollout step, as specified
in the plan and migration guide. No external repository was edited.
