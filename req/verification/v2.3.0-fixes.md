## HTTP and polling

- Raw socket tests cover stalled headers, stalled bodies after headers, a 64 MiB stalled upload, and trickled responses. Caller assertions allow the effective deadline plus 5 s of scheduling slack (7 s for the 2 s deadline, 6 s for the 1 s small-call cap). Connection-release assertions retain the separate 5 s bound.
- After timeout, peers drain buffered upload data and observe EOF/reset within 5 s. No new non-daemon client threads remain. Concurrent body stalls and a subsequent healthy request do not serialize their deadlines.
- Redirects, HTTP/1.1, the default proxy selector, auth, multipart Content-Length and error bodies are covered.
- TestKit verifies a stalled release upload returns promptly. Single-release and combined polling use the small-call cap, record/retry timeouts and never upload again. Combined submission records `UPLOAD_ERROR` when its upload response times out.
- Polling tests assert one upload and exact status counts for zero retries, exhaustion, 502, 429, malformed JSON, recovery, and immediate friendly 401/403 failures.
- Both timeout ranges accept 1 and 86400 and reject 0, negative values, 86401 and Integer.MAX_VALUE.

## Baseline regressions

An isolated copy compiled the original HTTP implementation from the pre-change commit. Controlled 5 s stalls made the old caller take 5319 ms (body), 5015 ms (upload) and 5047 ms (trickle), failing the original 3 s test bound. This baseline was recorded before the review widened timing assertions to deadline + 5 s; it is historical evidence of the missing caller deadline, not a claim that a 5 s stall fails the wider assertion. Peers deliberately released these baseline requests after 5 s rather than leaving the verification process hung indefinitely.

The dedicated JDK 17 ISO-8859-1 test failed with the original `getBytes()` auth encoding and passed with explicit UTF-8. The shell harness failed against the original single `clean build publishPlugins release` invocation and passed against the reordered script, including failure injection at each step and the sourced helper's unset-variable read.
